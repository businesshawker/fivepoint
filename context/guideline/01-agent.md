- 設計・実装仕様

### 設計・実装仕様
- **context/spec/N(-N)_XXX/02-requirement.md** とsrc内のソースコードを参照し、設計・実装仕様を作成すること
- 作成した設計・実装仕様は **context/spec/N(-N)_XXX/03-design.md** に設計・実装仕様書として文書化すること
- 既に存在する記述は参考にせず、今回文書化した内容を上書きして良い
- プログラムの実装方針を明文化すること
- メソッドは詳細設計を明文化すること
- パラメータは具体的に名称を決め数値を明文化すること

- 新規にメソッドを作成する場合は、メイン処理で呼び出す処理も合わせて設計すること
- 作成対象や修正対象のファイル名、メソッド名を記載すること、かつ新規作成なのか修正なのか分かりやすく記述すること

### 03-design.mdのテンプレート

## 資料化コマンド
**/doc -N** と入力されたら以下を順番に実行すること
- アーキテクチャ資料
- メソッド・関数コールチェーンのシーケンス図資料化
- 処理一覧資料化
- UI要素の名称資料化(UIがなければ作成しなくて良い)

### アーキテクチャ資料
- クラス構造やメソッド・関数の俯瞰した構成図をmermaid記法で作成し **context/doc/01-architecture.md** に出力すること
- 全てのメソッド・関数が網羅的に記載されていること
- 各クラスのメソッド・関数がどのファイルに記述されているか箇条書きで明記すること

### メソッド・関数コールチェーンのシーケンス図資料化
- メソッドや関数呼び出しのコールチェーンのシーケンス図をmermaid記法で **context/doc/02-callchain.md** に出力すること
- 全てのメソッド・関数が網羅的に記載されていること
- 何がきっかけでメソッドが呼び出されるかソフトウェア全体を分析し、それを呼び出しの先頭メソッドとすること
- きっかけを明記し、それを各コールドチェーンのタイトルとすること
- 同期呼び出しと非同期呼び出しを明確に記載すること
- 各クラスのメソッド・関数がどのファイルに記述されているか箇条書きで明記すること
- 戻りの矢印も省かずに記載すること

### 処理一覧資料化
- 各クラスの役割やメソッド・関数の引数・戻り値・内部処理を日本語で説明した文書を **context/doc/03-processor.md** に出力すること
- 全てのメソッド・関数が網羅的に記載されていること
- 各クラスの役割やメソッド・関数がどのファイルに記述されているか併記すること
- 引数や戻り値はどんなデータが格納されるか具体例を明記すること

### UI要素の名称資料化(UIがなければ作成しなくて良い)
- UIが存在するプロジェクトの場合は、UI要素の名称を命名し **context/doc/04-ui.md** に出力すること
- 全てのコンポーネント(ボタン・ビューア・ドロップするエリア)などが、網羅的に番号で記載されていること
- UIのレイアウトと要素位置を示す注釈付きSVGを **context/doc/04-ui.svg** に出力すること
- UIのレイアウトと要素位置を示す注釈付きSVGにコンポーネント番号と名称の注釈を埋め込むこと
- src配下のソースコードを基に加筆修正する場合、既に記載があり、ソースコード上変化がない記述は修正不要
