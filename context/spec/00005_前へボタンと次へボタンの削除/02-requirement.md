# 要件定義: 前へボタンと次へボタンの削除

## 背景/目的
- 本要件は、UI の「前へ」「次へ」ボタンと、キーボード左右キー（←/→）による画像移動を廃止することを目的とする。
- 削除に伴う機能退行（デグレード）が発生しないこと。

## スコープ
- 対象: 画像ビューアにおける前後移動のナビゲーション機能（UI ボタンと左右キー操作）。
- 非対象: フォルダ選択、再読み込み、評価変更（0–5 数字キー）、通番初期化、ドラッグ&ドロップでのコピー追加、実サイズ表示のドラッグ操作などその他機能。

## 機能要件
- UIボタン削除: 画面上に「前へ」「次へ」ボタンが表示されないこと。
- 左右キー無効化: ←/→ キー押下で画像の前後移動が発生しないこと。
- 代替操作維持: サムネイル一覧のクリックでの画像切替は従来通り可能であること。
- 評価操作維持: 数字キー 0–5 による評価変更は従来通り可能であること。
- 表示の安定性: 初期表示、画像読み込み、スクロール/ズーム/ドラッグ等の表示挙動は従来通りであること。

## 非機能/品質要件
- 退行防止: 以下の既存機能に動作影響がないこと。
  - フォルダ選択、再読み込み、自動 JPEG 変換
  - 通番のみ初期化、全て初期化
  - ドラッグ&ドロップによる画像のコピー追加
  - 実際の画像サイズで表示するモードのドラッグ移動
- エラーなし: コンソールエラー、未定義参照、不要なイベントリスナの残存がないこと。
- レイアウト健全性: ナビゲーション削除後もレイアウト崩れやクリック不能領域の残存がないこと。

## 受け入れ条件（受入テスト観点）
- UI表示:
  - 画面上に「前へ」「次へ」ボタンが存在しない（非表示ではなく DOM 不存在が望ましい）。
- キー操作:
  - ←/→ キーを押しても現在選択中の画像が変化しない。
  - 数字キー 0–5 では評価値が従来通りに変更される。
- 代替操作:
  - サムネイルをクリックすると該当画像へ切替できる。
- 回帰確認:
  - フォルダ選択→読み込み→サムネイル表示→画像表示まで一連の操作に問題がない。
  - 実サイズ表示モードでのドラッグ移動が従来通り機能する。
  - 画像のドラッグ&ドロップによる追加が通番で行われる。
  - コンソールにエラーが出力されない。
- 端点確認:
  - 最初/最後の画像で ←/→ キーを押下してもエラーや警告が発生しない。

## 制約/補足
- 実装では、ナビゲーション UI 要素（例: 前へ/次へに相当する要素）と左右キーのイベントハンドリングを安全に除去または無効化し、関連するスタイルや参照を整理すること。
- ショートカット表記やヘルプに左右キー移動が記載されている場合は、別途ドキュメント整備の対象とする（本要件の範囲外）。
